# 현업 사용 가이드 — 상세페이지 생성 하네스

> 독자: 비개발 마케팅 담당자(PoC 운영: 대웅 CH본부 BM2팀)
> 대상: 규제 대상 제품(화장품·의약외품·건기식·의약품)의 홍보/상세 자료 생성. 도메인·포맷은 사람이 선언한다.
> 짝 문서: 설계·구조는 [`harness-design.md`](harness-design.md) 참조. 이 문서는 **"실제로 어떻게 쓰는가"**만 다룬다.
> 예시 실행(화장품 PoC 샘플 — 교체 가능): 이지듀 멜라 비 토닝 앰플 쿠션 (실행 이름은 임의, 예: `my-product-2026`)
>
> ⚠️ **입력 모델 v1.1.** 별도로 손으로 채우는 `product-meta.json`은 **없다.** 제품 근거(기능성·성분·실증)는 워킹백워드에서 자동 추출되고(`claim-basis.json`), 법적으로 민감한 표현만 한 번 확인받는다. (정정 사유는 §8 참조. 설계 문서 `harness-design.md`도 v1.1로 동기화 완료 — 두 문서 일치)

## 1. 한눈에 — 당신이 하는 건 "4가지"뿐

상세페이지의 생성·심의·재시도·상태관리는 전부 하네스가 한다. **사람은 이 4가지만** 한다.

| 동작 | 명령 (또는 슬래시) | 의미 |
|---|---|---|
| 👀 **본다** | `open <파일>` | AI가 만든 산출물을 읽어본다 |
| ✅ **승인** | `bash scripts/approve.sh <실행이름>` · `/approve` | "좋아, 다음 단계로" |
| ✍️ **보완 요청** | `bash scripts/revise.sh <실행이름> "고칠 내용"` · `/revise "..."` | 자연어 한 줄 → 재생성 |
| 🔀 **선택** | `bash scripts/select.sh <실행이름> B` · `/select B` | 여러 안 중 하나 고르기 |

그리고 **무엇을 할지 외울 필요가 없다.** 진행 보드 `run.md`가 항상 "지금 할 일 + 다음에 칠 명령"을 알려준다. 막히면 `/status` 한 번.

> 💡 명령이 길어 보여도 매번 `run.md`에서 **복사해 붙여넣기**만 하면 된다. JSON·코드를 직접 만질 일은 없다.

## 2. 준비물 — 처음에 넣는 "3가지"

상세페이지 하나를 만들려면 아래 3가지를 폴더에 넣는다. **이게 전부다.**

### ① 워킹백워드 (제품 학습 문서) — `inputs/working-backwards.md`
- 기존 `.docx` 워킹백워드 내용을 그대로 붙여넣는다.
- 여기에 **제품의 모든 근거가 들어있다**: 작용 기전, 유효성분, 인체적용시험 결과, 인증(예: FDA·식약처·알러지협회), 제품유형(화장품/의약외품), 특장점.
- 👉 **이 문서가 "법적으로 주장 가능한 것"의 근거 원천이다.** 별도 입력을 또 만들 필요 없음.

### ② 자사 이미지 산출물 — `inputs/assets/`
- 우리가 **이미 가진 이미지**를 넣는다: 한 장짜리 홍보 이미지부터 여러 장의 BM 이미지까지.
- 👉 이건 **디자인 단계에서 실제로 페이지에 들어가는 소재**다. (저작권 때문에 크롤 이미지는 못 쓰므로, 자사 이미지가 디자인의 핵심 재료)
- 이미지가 적으면 적은 대로 진행되고, 부족한 부분은 도형/타이포 기반 섹션으로 채운다.

### ③ 크롤링된 Best Practice — 크롤 폴더 그대로
- 수동으로 받아둔 경쟁/자사 상세페이지 크롤 번들 폴더(`product.json`·`reviews.csv`·`images/` 구성; 테스트 예: `tests/fixtures/bundle-cosmetic`).
- 👉 이건 **"구조·흐름 참고용"**이다: 좋은 상세페이지가 어떤 순서로 섹션을 배치하는지, 소비자가 리뷰에서 어떤 말을 쓰는지를 학습한다. **픽셀을 베끼지 않는다.**

> ❗ **product-meta.json 같은 걸 따로 작성하지 않는다.** (예전 설계에 있었지만 정정됨 — §8)

## 3. 시작하기 (명령 2개)

```bash
# 1) 작업 공간 만들기 (규제도메인·산출물 포맷을 반드시 선언 — 미선언은 fail-closed 중단)
bash scripts/new-run.sh easydew-cushion-2026-06 --domain 화장품 --format 여러장

# 2) 재료 정리: 리뷰 분석 + 워킹백워드에서 근거 자동 추출
bash scripts/ingest.sh easydew-cushion-2026-06 <크롤번들폴더>
```

`ingest`가 자동으로 하는 일(전부 결정적, AI 환각 없음):
- 리뷰(`reviews.csv`)를 분석해 **소비자가 실제로 쓰는 말**을 뽑는다 → `voc.json` (예: "커버·기미·촉촉·화사"가 많고 "주름"은 0건).
- 워킹백워드에서 **성분·기능·인증·제품유형·실증자료**를 추출 → `claim-basis.json` ("주장 가능 근거표").
- 자사 이미지 목록 정리.

> 🔒 **안전 기본값**: 워킹백워드에 근거가 없는 효능은 자동으로 **"주장 불가(unknown)"**로 표시된다. AI가 마음대로 효능을 지어내지 못한다.

## 4. 반복 루프 — 이 리듬이 4번 반복될 뿐

모든 단계가 **똑같은 5스텝**이다.

```
①  run.md 를 연다 → "지금 할 일" 확인
②  안내된 생성 명령 1개 실행   → AI가 산출물 생성, 심의 서브에이전트가 자동 체크
③  결과 파일을 열어 본다
④  승인 / 보완 / 선택  중 하나
⑤  run.md 가 다음 단계로 안내 → 반복
```

핵심: **심의를 통과한 안들만 당신에게 올라온다.** 심의가 "이 표현 위험"이라고 하면, 당신한테 오기 전에 AI끼리 한 번 고친다. (무한 반복은 `max_iterations`로 막혀 있어, 못 고치면 "사람이 봐주세요"로 멈춘다)

## 5. 4페이즈 워크스루 (실제 화면 흐름)

### 0️⃣ 브리프 (자동 + 한 번 확인)
- ingest 결과로 브리프가 자동 합성된다.
- 당신이 하는 일: **법적으로 민감한 표시만 한 번 확인.**
  ```
  run.md → "확인해 주세요: 이 제품의 기능성 표시 = [미백] 으로 추출했습니다. 맞나요?"
  맞으면:  bash scripts/approve.sh easydew-cushion-2026-06
  틀리면:  bash scripts/revise.sh easydew-cushion-2026-06 "기능성 표시는 자외선차단만"
  ```

### 1️⃣ 컨셉 / 빅 아이디어 (RTB·키메시지)
```bash
bash scripts/run-stage.sh concept easydew-cushion-2026-06     # 또는  /concept
```
- AI가 **서로 다른 컨셉 축으로 3안**을 따로 만든다 → `A-효능중심 / B-감성·자기관리 / C-성분·과학`.
- 각 안은 리뷰의 **실제 소비자 언어를 인용**하고, 효능 주장엔 **근거(워킹백워드 출처)가 붙어야** 심의를 통과한다.
- `run.md`에 심의 서브에이전트의 **추천(top-1)**이 표시된다.

당신이 하는 일:
```bash
open runs/easydew-cushion-2026-06/02-concept/options/B-emotional/key-message.md   # 본다
bash scripts/select.sh easydew-cushion-2026-06 B                                   # B안 선택
# 마음에 안 들면:  bash scripts/revise.sh easydew-cushion-2026-06 "기미 단정 표현 빼고 '톤 보정'으로"
```

### 2️⃣ 콘티 / 스토리보드 (스토리라인 → 기획안)
```bash
bash scripts/run-stage.sh storyboard-outline easydew-cushion-2026-06   # 스토리라인 2안
```
- **한국형 12블록 구조**(후킹→문제공감→성분·기전→근거·인증→사용법→비교→후기→FAQ→CTA…)에 컨셉을 배치한 **전개 2안**.
- "실증이 필요한 표현"이 감지되면 **논문 검색(OpenAlex 직접 HTTP)을 자동 호출**해 근거 후보를 모은다(오프라인 CI[`HARNESS_OFFLINE=1`]는 결정적 stub; 온라인 네트워크/엔진 오류는 조용한 강등 없이 fail-closed). 모인 결과는 검증 전 발견 후보라 자동 인용되지 않고, 채택 여부는 사람(현업/RA)이 판단한다.
- → 본다 → `select.sh` 로 전개 확정.

```bash
bash scripts/run-stage.sh storyboard-plan easydew-cushion-2026-06      # 기획안 본문
```
- 블록마다 헤드라인·본문이 채워지고, **주장에는 근거 각주가 짝지어진다**(심의 핵심).
- → 본다 → `approve.sh` 로 기획안 승인.

### 3️⃣ 키비주얼 / 아트워크 (← 진짜 "디자인"이 나온다)
```bash
bash scripts/run-stage.sh keyvisual easydew-cushion-2026-06     # 또는  /keyvisual
```
- AI가 기획안 + **당신이 넣은 자사 이미지(`inputs/assets/`)**를 조합해 **HTML/CSS 세로 섹션 상세페이지 2안**을 만들고, 화면을 **렌더해 섹션별 이미지(PNG)**까지 뽑는다.
- 디자인은 멀티모달 심의(전후사진·의료 모티프·영문 카피까지)를 거친다.
- → 시안 2안을 눈으로 비교 → `select.sh A` → `approve.sh`(최종 승인).

## 6. 심의는 지금 어떻게 도나 (현 시점 구현)

- 협회 검사 에이전트(P-AX-05-01)는 **아직 구현 전**이다.
- 그래서 현재는 **심의가이드 문서를 읽는 별도 서브에이전트**가 심의를 한다:
  - `docs/regulation/`에 둔 심의가이드 문서(화장품 광고 자문 해설서 2025·식약처 표시광고 지침)를 컨텍스트로 받은 **별개의 서브에이전트**(=글을 쓴 AI와 다른 세션 → 자기 글 자기 채점 방지)가 산출물을 검사한다.
  - 결과는 `verdict.json`(통과 / 수정필요 + 위반 항목 + 수정 제안)으로 남는다.
- 👉 나중에 협회 에이전트가 완성되면 **같은 `verdict.json` 인터페이스로 교체**만 하면 되고, 현업 사용법은 안 바뀐다.

> 주의: 심의 서브에이전트는 **"제출 전 셀프체크"**다. 협회 자문(자율·비법적)이나 식약처 최종 책임을 대신하지 않는다. 마지막엔 사람이 본다.

> **운영자 메모(셸로 직접 돌릴 때):** 심의(원격 ADK 다중 패스)와 키비주얼 이미지 생성은 정상적으로 **수 분~십수 분** 걸린다. 한 번의 명령으로 끝까지 기다리지 말고 **백그라운드로 띄우고 30~45초 간격으로 상태만 확인**한다(오래 걸리는 한 방 실행은 세션이 죽을 수 있다):
> ```bash
> mkdir -p "runs/$RUN/.logs"
> nohup bash scripts/kcia-check.sh "$RUN" </dev/null >"runs/$RUN/.logs/kcia-bg-$(date +%s).log" 2>&1 &
> # 이후 30~45초 간격: kill -0 <PID>(생존) · tail runs/$RUN/.logs/kcia-bg-*.log(진행) · verdict.json 갱신+run.md 확인(완료)
> ```
> 키비주얼 이미지 생성(`run-stage.sh keyvisual`)도 같은 방식으로 띄우고, `04-keyvisual/image-manifest.json` 에서 `incomplete` 가 사라지면 완료다. 중단은 자식까지: `pkill -P <PID>`.

`runs/easydew-cushion-2026-06/04-keyvisual/` 안에:

- 📦 **협회 자문 신청 패키지** — `export/kcia-package/` (시안 + 근거 목록 + 매체 구분)

중간에 며칠 쉬었다 와도 `run.md`만 다시 열면 그 자리에서 이어진다. 다른 사람(또는 다른 PC)이 이어받아도 된다.

> **운영자 메모(에이전트 수명주기 규율 · O-9):** 이 하네스를 대신 돌리는 AI 에이전트(운영자)는 오래 도는 작업 중 세션이 끊길 수 있다. 이때 두 가지를 지킨다 — ① **경량 컨텍스트 유지**: 대용량 원문(워킹백워드 전문·크롤 번들·긴 로그)을 통째로 다시 읽지 말고 필요한 부분만 본다(컨텍스트가 무거우면 세션이 더 잘 끊긴다). ② **상태 기반 이어받기**: 진행 상태의 진실은 항상 `state.json` + `run.md` 에 있다. 세션이 끊기면 새 에이전트가 그 파일들의 "지금 할 일 / 다음 명령" 지점부터 그대로 재개하면 된다(중간 기억을 붙들 필요 없음). 실제 E2E 에서 이 방식으로 세션이 여러 번 바뀌어도 done 까지 완주했다.

## 8. 왜 입력이 "3가지"로 정정됐나 (product-meta.json 삭제 사유)

설계 초안에는 사람이 손으로 채우는 `product-meta.json`(기능성·성분·실증 표)이 **필수 입력**으로 있었다. 정정한 이유:
- 그 입력은 검증 단계에서 **"AI가 효능을 지어내는 걸 막자"**는 좋은 의도로 들어왔다. (크롤 데이터엔 기능성/실증 정보가 0건이었기 때문)
- 그러나 그 판단은 **워킹백워드 문서를 보지 않은 상태**에서 내려졌다. 실제 워킹백워드엔 성분·인체적용시험·인증·제품유형이 **이미 다 들어있다.**
- 따라서 사람이 **JSON을 또 쓰게 하는 대신**, ingest가 워킹백워드에서 근거를 **자동 추출(`claim-basis.json`)**하고, 법적으로 민감한 표시만 브리프에서 **한 번 확인**받는 방식으로 바꿨다.
- **"근거 없으면 주장 못 한다(fail-closed)"는 안전 원칙은 그대로** 유지된다. 사람의 입력 부담만 사라졌다.

## 9. 자주 막히는 곳 (FAQ)

- **Q. "기능성 표시 확인해 달라"고 멈춰요.** → 정상이다. 워킹백워드에서 추출한 기능성 표시(미백/주름/자외선차단)가 맞는지 확인하는 게이트다. 맞으면 `approve.sh`, 틀리면 `revise.sh`로 바로잡는다.
- **Q. 효능 문구가 너무 약해요.** → 그 효능의 근거가 워킹백워드에 있으면 근거를 추가하면 강해진다. 근거가 없으면 법적으로 못 쓰는 표현일 수 있다(심의가 막은 것).
- **Q. 자사 이미지가 거의 없어요.** → 있는 만큼만 쓰고 나머지는 타이포/도형 섹션으로 채워 초안을 만든다. 나중에 이미지를 추가해 다시 `keyvisual`을 돌리면 된다.
- **Q. 잘못 승인했어요.** → `revise.sh`로 보완 요청하면 해당 단계가 다시 열린다. 모든 이력은 파일로 남아 되돌릴 수 있다.
- **Q. Claude로 시작했는데 Codex로 이어도 되나요?** → 된다. 상태가 전부 파일(`run.md`/`state.json`)에 있어 어느 도구로 열어도 같은 자리에서 이어진다.
