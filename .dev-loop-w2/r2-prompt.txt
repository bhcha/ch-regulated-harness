집어 처리하는 파일 기반 큐의 규약 v2. 절대 마감(expires_at) + 클레임-by-rename + 클레임 전 2중 검사 +
v1 레거시 잡 구분(no_deadline) + 화해 버튼([상태 다시 확인]/[다시 만들기]) + reaper 가 핵심이다.

특히 파고들 것 (브리프 2번 절과 함께):
- TOCTOU: 2중 검사와 rename 사이의 창
- 두 소비자의 rename 경합에서 패자의 운명(조용한 실패? 중복 처리?)
- reaper 가 살아있는 느린 소비자를 고아로 오인해 재큐 → 이중 실행
- 시계 처리: 깨진/미래/음수 expires_at 의 폴백이 '안전한 쪽(집지 않음)'인가
- [다시 만들기]가 클레임된 잡을 되살리는 경로가 있는가(불변식 7 위반)
- 봇의 회수(reclaim)와 소비자 클레임의 경합
- failed/ 격리 자체가 실패하면 잡이 조용히 사라지는가

산출 형식: 발견마다 severity(critical/high/medium/low) · 파일:라인 · 위반한 불변식 번호 ·
재현 시나리오(구체적 입력/상태 → 잘못된 결과). critical/high 가 0 이면 그렇게 판정하라 —
없는 결함을 만들지 마라. 마지막에 한 줄 판정: "R2 판정: critical/high N건".
