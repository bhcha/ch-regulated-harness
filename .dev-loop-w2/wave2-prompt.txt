## 설계 전제(이게 성립하는지가 리뷰의 핵심)
- 읽기 경계 = **cwd(`core/runs/<rid>`) + --add-dir 4종**. 열거가 아니라 구조다(A-4).
- 실행 경계 = **승인 게이트의 헤드리스 fail-closed**. `--allowedTools` 는 제한 장치가 아니라 **예외 등록**이다(A-3).
- deny(격리 CONFIG_DIR settings)는 **경계 안쪽을 파내는 예외**(state.json·run.md·.lock 쓰기 금지 등)이지
  읽기 허용목록이 아니다(A-3: deny 가 allow 를 이기므로 '전부 deny + 내 것만 allow' 는 불가).
- `--bare`·`--dangerously-*`·`bypassPermissions` 금지(A-6 = API 과금 경로 → 잠긴 결정 6 위반).

## ★ 구현자가 발견해 **판정을 요청한 것**(이번 라운드의 최우선 항목)
**프로젝트/로컬 settings 소스가 무인 세션의 경계를 넓힐 수 있다.**
- 부록A-9 의 dry-run 은 레포 **밖** 스크래치 픽스처에서 돌았다. 그런데 운영 cwd 는 `core/runs/<rid>` = **레포 안**이다.
- 격리 `CLAUDE_CONFIG_DIR` 는 **사용자** 설정만 가린다. 프로젝트 설정(`.claude/settings.json`·`settings.local.json`)은
  cwd 에서 위로 탐색되므로 **CONFIG_DIR 격리로 막히지 않는다**(구현자 주장 — 검증하라).
- 실측: 레포 루트 `.claude/settings.local.json` 에 allow 9건이 실재한다. 그중
  `Bash(bash scripts/select.sh ezderm-beauty-20260623 B-usevalue)`(**결정 명령**),
  `Read(//Users/chabh/Documents/temp/**)`·`Read(//Users/chabh/Downloads/NAVERWORKS/**)`(**cwd 밖 절대 읽기**).
- 이 파일은 **현업/운영자가 대화형 세션에서 '허용'을 누를 때마다 자란다** → 무인 세션의 경계가 조용히 넓어진다.
  잠긴 결정 2/3 의 "경계는 워커 코드가 보증한다 · CONFIG_DIR 는 워커 소유라 사용자 설정이 애초에 없다"와 충돌한다
  (계획은 **프로젝트 설정을 고려한 적이 없다**).
- 구현자는 `--setting-sources user` 를 후보로 봤으나 **적용하지 않았다**: 틀리면 우리 자신의 deny settings 를
  조용히 떨어뜨리기 때문(조용한 약화 > 시끄러운 실패). 미실측이라 추측 금지 원칙을 따랐다.

**판정하라**: ⑴ 프로젝트 settings 가 실제로 무인 세션에 적용되는가(코드/문서 근거로). ⑵ 적용된다면 severity 는?
(오늘의 노출: select.sh 규칙은 타 rid 핀 + 상대경로라 run cwd 에서 미존재 · 그러나 `Read(//Users/...)` 는 절대경로다.
allow 규칙이 A-4 의 cwd 기본거부 경계를 **덮을 수 있는가**가 관건 — 미실측이면 그렇다고 말하라.)
⑶ 지금 코드에서 할 수 있는 fail-closed 조치가 있는가, 아니면 W5 라이브 카나리로 미뤄야 하는가.

## 그 외 구현자가 스스로 밝힌 것(독립 검증)
1. **`-p` 는 boolean 이고 프롬프트는 positional 이다.** SKILL.md 는 `---`(frontmatter)로 시작해 파서가 옵션으로 읽는다
   → `--` 종결자 없이는 **모든 SKILL.md 프롬프트가 1행에서 죽는다**. 파서 레벨 프로브(2.1.212, unknown-option
   대조군)로 확인해 argv 를 `… --disallowedTools <rules> -- <prompt>` 로 끝냈다. 이 논증이 맞는가?
2. **다중 `--allowedTools` argv 형태는 미실측**(부록A 에 기록 없음). 규칙별 토큰으로 조립하고 코드 주석에
   "미실측 — W5 카나리"로 표시했다. 규칙에 공백이 있어 1토큰 결합은 구분자 파싱을 CLI 에 위임하게 된다는 근거.
   틀리면 fail-closed(전이 거부 → next-action 정체 = A-9 의 1차 실패 형태)라는 주장은 맞는가?
3. `Read(//abs/**)` 절대 글롭 사용(A-3 은 `Read(//**)` 만 실측 · 상대 규칙의 기준 디렉터리가 불명이라 질문 자체를 삭제).
   Write/Edit 절대 글롭 철자는 **미실측** — 틀리면 deny 가 **조용히 무효**(신호 없음)라고 스스로 밝혔다.
4. `.lock` 은 디렉터리(core 의 mkdir 락)라 루트와 `/**` 둘 다 deny. `apply-*` 는 오늘 `apply-learnings.sh` 만 독립 스크립트.
5. 프로브 중 **실 세션 1턴이 실수로 1회 실행됐다**(이후 tripwire-only 로 전환). 과금 귀속 게이트(ⓓ)는 여전히 미해소다.
