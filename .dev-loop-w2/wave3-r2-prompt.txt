## 적용된 수정
1. **[high#1 토폴로지 구멍 + 거짓 주석]** — 당신 판정 수용: 세션 detached 는 유지(손자 회수에 필요)하되
   ① `kill(-supervisorPID)` 가 트리를 회수한다는 **거짓 주석 정정**(음수 PID 는 그 PGID 하나만 겨냥) ②
   supervisor 가 **SIGTERM/SIGINT/exit 핸들러**로 자기 종료 전에 살아있는 세션 하위그룹을 `kill(-sessionPgid, SIGKILL)`
   전파 ③ 세션 pgid 를 **하트비트 파일**(`CHAT_SUPERVISOR_HEARTBEAT`, 미설정 시 no-op)로 노출해 W4 데몬이 직접 겨냥 가능 ④
   모듈 헤더에 **W3↔W4 계약** 명시(데몬은 supervisor 에 SIGTERM 먼저 or 노출된 세션 pgid 직접 kill · 맨몸
   `kill(-supervisorPID, SIGKILL)` 은 불충분 — SIGKILL 은 트랩 불가). 잠긴 결정 4 kill 메커니즘 변경 = 사람 승인 대상으로 표기.
2. **[high#2 close≠사망]** — `onSelfExit` 이 `groupAlive(pgid)` 참이면 settle 안 하고 반환(TERM/KILL/reap 알람 유지) →
   리더가 손자 남기고 종료해도 성공(exited)으로 안 닫는다. 단일 settle 보장 유지.
3. **[high#3 조기 알람 미재예약]** — 1회성 3알람을 자기재예약 `armNext()` 로: 조기 발화 시 남은 절대 델타로 재-arm ·
   setTimeout 상한(2^31-1) 넘으면 bounded hop 으로 재-arm. 늦은 발화의 절대시각 캐치업은 불변.
4. **[high#4 복구 과권한]** — 복구 argv 의 `--tools` 를 `Bash` 하나로 축소(`restrictRecoveryTools`, `--tools` 부재 시
   fail-closed). **cli-session.ts 미변경**(소유 밖이라, buildSessionPlan 에 tools 파라미터 추가는 미래 리팩터로 표기).

## ★ 판정 요청 — 토폴로지·계약(이번 라운드 최우선)
당신은 W3 에서 "detached 하위그룹은 유일하지도 최선도 아니다 · 재합의 대상"이라 했다. 구현자는 detached 를 **유지**하고
전파+노출+계약명시로 구멍을 닫았다. 판정하라:
⑴ 이 처방이 **high#1 의 마감 구멍을 실제로 닫는가**(전파 경로 · 하트비트 노출 · 계약)? 남은 구멍은?
⑵ **SIGKILL 잔여**를 정직히 다뤘는가 — supervisor 를 데몬이 SIGKILL 하면 핸들러가 안 도는데, 이걸 '해결한 척'
   하지 않고 W4 계약으로 넘겼는가, 아니면 은폐했는가?
⑶ `installSupervisorTerminationHandlers` 자체의 결함: exit 핸들러에서 async kill · 핸들러 재진입 · `host.exit`
   가 다른 리스너를 삼키는 문제 · `pgid>1` 가드가 `kill(-1)` 참사를 실제로 막는가.
⑷ 이 변경이 **잠긴 결정 4 재합의 대상**임을 코드가 올바르게 표기했는가(Wave1 리스 변경과 같은 격).
